# Правила работы в репозитории

## Граница секретов

- Никогда не открывать, не читать, не изменять, не удалять и не искать содержимое файлов `.env*`, кроме буквального файла `.env.example`.
- Не выполнять команды, которые могут неявно раскрыть секреты: вывод переменных окружения, `docker compose config` с реальным окружением, дампы контейнеров или процессов.
- Не просить пользователя присылать API-ключи в чат, команды или файлы репозитория.
- `.env` создаёт и заполняет только пользователь. Агент работает с `.env.example` и тестовыми значениями.
- Если команда может автоматически прочитать `.env`, использовать явный безопасный env-файл либо остановиться.

## Порядок реализации

- До отдельного подтверждения пользователя разрешены только документы, ADR, `.gitignore` и `.env.example`.
- После подтверждения выполнять шаги из `docs/plan/` по порядку и закрывать критерии выхода каждого шага.
- Существенное отклонение от утверждённой архитектуры сначала оформлять новым или обновлённым ADR.

## Python и зависимости

- Использовать только локальное окружение `.venv`; не устанавливать Python-пакеты глобально.
- Runtime-зависимости фиксировать в `requirements.txt`, инструменты разработки — в `requirements-dev.txt`.
- Команды Python запускать через интерпретатор текущего виртуального окружения.

## Инварианты продукта

- Генератор использует только факты, переданные во входном JSON. Runtime-поиск и автоматическое обогащение из интернета запрещены.
- `catalog-importer` является отдельным one-shot компонентом: не добавлять ему HTTP endpoint, UI-trigger или daemon-режим.
- Не выполнять массовый обход товарных страниц; полный YML индексируется одним запросом, страницы обогащаются только по явно выбранным offer ID.
- Технические значения нельзя придумывать, пересчитывать или незаметно перефразировать.
- Значения ключевых характеристик копируются из `specs`; LLM может выбирать только их порядок и состав.
- Любой результат является черновиком и требует решения контент-менеджера.
- Ключ, proxy credentials, полный prompt и полный LLM-ответ не попадают в логи.
- Реальный LLM smoke-тест выполняет пользователь. Автотесты работают без секретов через mock transport/provider.

## Качество изменений

- Документация и UI — на русском; код, модули, типы и идентификаторы — на английском.
- Не добавлять БД, авторизацию, историю, CMS или web-enrichment без отдельного решения.
- Сохранять слои: HTTP/API → application service → provider interface. Домен не зависит от HTTP-клиента.
- Изменение контракта сопровождается тестом и обновлением `docs/api/http-contract.md`.
