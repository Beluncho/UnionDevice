# ADR-0005: Catalog importer как отдельный one-shot сервис

Статус: accepted.

## Контекст

YML содержит десятки тысяч базовых offer, но подробные характеристики находятся на товарных страницах. Нужно воспроизводимо готовить примеры и при необходимости получать локальный каталог, не превращая MVP в CMS или scraper API.

## Решение

Разместить в монорепозитории отдельный компонент `catalog-importer` с собственными package boundary, тестами, requirements и Dockerfile. В Compose он объявлен как service профиля `tools`, запускаемый только через `docker compose run --rm`.

Importer поддерживает четыре CLI-команды: полный YML `index`, локальный `search` по JSONL-индексу, выборочный `enrich` по offer ID и `prepare-examples`. Он не имеет HTTP API, не вызывается UI и не импортируется backend.

## Последствия

- Полный YML можно получить и обработать одним потоковым запросом.
- Нужный товар выбирается локальным поиском по индексу до запуска enrichment.
- Подробные страницы не обходятся массово; enrichment ограничен выбранными товарами.
- Большой индекс/cache не попадает в Git и runtime application.
- В будущем importer можно вынести в scheduled job без изменения backend-контракта.

## Отклонено

- Backend endpoint для запуска importer: долгие внешние запросы, SSRF и смешение ответственности.
- Кнопка импорта в UI: требует auth, очереди, прогресса и хранения.
- Обогащение всех товаров: избыточная нагрузка на внешний сайт и отсутствие задачи для этих данных.
