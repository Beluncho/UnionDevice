# Backend service

## Ответственность

Backend принимает товар, управляет LLM-вызовом, проверяет grounding и возвращает единый контракт. Он не хранит данные и не выполняет интернет-поиск.

## Модули

- `api`: маршруты, dependency wiring, обработчики ошибок.
- `schemas`: входные, внутренние и публичные Pydantic-модели.
- `services`: orchestration генерации и анализ полноты.
- `providers`: интерфейс и OpenAI-compatible HTTP adapter.
- `validation`: ограничения результата и grounding.
- `rendering`: детерминированный Markdown.
- `prompts`: версионируемые prompt-шаблоны.

## Правила входа

- `name`: непустая строка, обязательна.
- `manufacturer`: nullable; пустая строка нормализуется в `null`.
- `specs`: объект строковых ключей/значений; пустые пары удаляются либо возвращают локализованную ошибку согласно контракту.
- `description`: nullable; пробельная строка считается отсутствующей.
- Требуется хотя бы одно: непустой `specs` или `description`.

## Правила результата

- Модель возвращает title, description, search queries, commercial block и ordered list ключей характеристик.
- Каждый выбранный ключ обязан существовать во входном `specs`.
- Значения характеристик берутся только из входного словаря.
- Если `specs` пуст, API возвращает характеристику `Данных нет` и `needs_clarification`.
- Markdown строится кодом из уже проверенной публичной модели.

## Ошибки и повторные попытки

- Один корректирующий LLM-вызов при неверной схеме или нарушении контентных ограничений.
- Ограниченный transport retry применяется только к временным сетевым ошибкам/429/5xx и не скрывает окончательную причину.
- Ошибки провайдера преобразуются в стабильные публичные коды; тело upstream-ответа клиенту не возвращается.

## Логи

Разрешены request ID, маршрут, длительность, HTTP/provider status, модель и число попыток. Запрещены ключи, proxy credentials, полный prompt, описание товара и полный ответ LLM.
