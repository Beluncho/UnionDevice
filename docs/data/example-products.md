# Подготовка демонстрационных товаров

## Источники

YML-фид содержит базовые offer-поля, но почти не содержит описаний и подробных характеристик. `catalog-importer` поэтому выполняет два шага: находит offer в YML и извлекает описание/таблицу характеристик со страницы товара.

Зафиксированные offer:

- `58444` — `testo 510`, дифференциальный манометр.
- `64423` — `testo 830-T1`, пирометр.

## Catalog importer

Отдельный компонент `catalog-importer`:

- принимает URL YML либо путь к локальному `feed.xml`;
- использует browser-like `User-Agent`, timeout и понятные ошибки;
- может потоково записать все базовые offer в локальный JSONL-индекс;
- обогащает страницы только явно выбранных offer;
- читает JSON-LD для имени/бренда и DOM-секции описания/характеристик;
- исключает цену, наличие, отзывы, изображения, упаковку и ссылки;
- пишет нормализованные UTF-8 JSON в `examples/inputs/`.

HTML разбирается BeautifulSoup с `html.parser`; полный HTML страниц в репозиторий не сохраняется.

Полный JSONL-индекс и сетевой cache сохраняются в `data/catalog/`, игнорируются Git и не используются runtime-приложением.

## Fixtures

- `testo-510.json` — полный товар.
- `testo-830-t1.json` — полный товар.
- `testo-510.partial.json` — тот же товар без `description`, но с типом прибора и сокращённым набором подтверждённых характеристик.

Partial-файл генерируется детерминированно из полного fixture и не редактируется вручную.

## Результаты

Автотесты используют fake provider. Реальные output JSON/Markdown создаёт smoke-клиент после пользовательского запуска с настроенным `.env`. Сохранённые результаты можно проверять и коммитить: секретов в них нет.
