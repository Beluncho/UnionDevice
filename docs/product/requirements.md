# Требования к MVP

## Цель

Сократить ручную подготовку черновика товарной карточки, не подменяя проверку контент-менеджера и не добавляя факты, которых нет во входных данных.

## Пользовательские сценарии

1. Менеджер заполняет форму или вставляет JSON товара.
2. Сервис проверяет достаточность и отправляет подтверждённые данные в LLM.
3. Менеджер получает структурированный черновик и Markdown для копирования.
4. Если данных недостаточно, сервис сохраняет черновой режим, перечисляет пробелы и помечает карточку `needs_clarification`.
5. Менеджер вручную сверяется с паспортом, производителем или поставщиком, дополняет вход и повторяет генерацию.

## Обязательный результат

- SEO-заголовок не длиннее 70 символов.
- SEO-описание длиной 800–1200 символов.
- Список ключевых характеристик с исходными значениями.
- 3–5 уникальных поисковых запросов.
- Краткий commercial-блок: аудитория и решаемые задачи.
- JSON и Markdown-представления одного результата.

## Состояния

- `draft_ready`: основные группы данных заполнены, ответ прошёл автоматические проверки.
- `needs_clarification`: отсутствует производитель, описание или характеристики; проверенный draft возвращается, только если ответ LLM прошёл validator.
- Ошибка `insufficient_product_data`: нет названия либо одновременно отсутствуют и описание, и характеристики.

Оба успешных состояния остаются черновиками и требуют ручного одобрения.

## Не входит в MVP

- Публикация в CMS, хранение истории, БД, аккаунты и роли.
- Автоматический поиск характеристик и переход по ссылкам из пользовательского ввода.
- Нативные адаптеры Anthropic/Google и выбор нескольких провайдеров в UI.
- Определение того, какие характеристики обязательны для каждой категории прибора.

## Критерии приёмки

- Ни одного технического значения нет вне входного товара.
- Неполный пример явно отличается от полного в API и UI.
- Все автоматические тесты выполняются без API-ключа.
- Проект запускается локально и через Docker Compose по README.
